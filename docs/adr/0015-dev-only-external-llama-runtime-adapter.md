# ADR-0015 — Dev-only, loopback-only external llama.cpp runtime adapter (v0.1 first local-model chat)

**Status: Accepted** Revision 4 (2026-10-24): the owner's twelve refinements (revision 2), the remediation of the independent Codex review (BLOCKED; seven findings accepted and corrected, see the end of the Decision section), and the closure patch after its focused re-review (PASS WITH CONDITIONS; the repeated-`Content-Length` framing gap, launcher artifact ownership, the retained-intent recovery procedure and the operating conditions of the first smoke). A development-only implementation exists for review (see Implementation status) and remains subject to owner acceptance of this ADR. Scope: the macOS development host. Not an access-capable build, not Windows, not a V0 acceptance. It adds a narrow, bounded acceptance beside [ADR-0013](0013-execution-attempt-lifecycle-and-release-evidence.md), which did **not** accept any external-runtime mechanism and says that until measured only scripted adapters may claim bases B3–B5. It supersedes nothing and changes no LD-04 classification.
**Date:** 2026-10-24.

## Context

Slice 0B-1 is closed against a scripted, in-process runtime. E1, E2-B and the closed E3 V1 pilot ([record](../evidence/v0-0b2-e3-first-pilot-run.md)) measured one pinned `llama-server` b11440 with `Qwen3-4B-Q4_K_M` on the Mac. They support a conditional B4 basis only in the harness-owned, single-process, no-fork configuration (n=1) and show that the runtime **survives its Owner's death and finishes the request it accepted** (observation O5). B3, B5, cancel, disconnect and `late_delivery_excluded` are `NOT_TESTED`; every LD-04 row remains `BLOCKED_BY_RUNTIME_EVIDENCE`. The owner has decided that successor-side B4 evidence must not by itself authorize release of an external-runtime binding.

The read-only integration trace found, in the accepted 0B-1 code:

- **F1.** `publish_response` hard-codes `termination_basis = runtime_reported_terminal`, `completion = yes` on every successful T4 ([store.py:854-855](../../server/src/anonymous/adapters/persistence/sqlite/store.py#L854)); T4 needs only an open fence, `STARTED` and epoch 0b ([0002 SQL:241-244](../../server/src/anonymous/adapters/persistence/sqlite/versions/0002_ld04_execution_ownership.sql#L241)) and never consults `declared_bases`. A real external adapter would write a B3-labelled stamp on every success.
- **F2.** Every B3-shaped settlement ends in `RunSettler.apply_evidence`, which checked only the handoff state, not `declared_bases` or scope. The call paths (all inspected):

  | Path | Entry | Reaches `apply_evidence` as |
  |---|---|---|
  | Delivery after closure or settlement | [worker.py:364-366](../../server/src/anonymous/application/worker.py#L364) → `late_delivery` ([settling.py](../../server/src/anonymous/application/settling.py)) | B3 if the delivering `instance_ref` equals the binding |
  | Terminal failure reported `ENDED` | [worker.py:368-371](../../server/src/anonymous/application/worker.py#L368) → `_settle_known` | B3 |
  | Model mismatch, truncated, empty completion | [worker.py:383-391](../../server/src/anonymous/application/worker.py#L383) → `_settle_known` | B3 |
  | Response not saved | [worker.py:447](../../server/src/anonymous/application/worker.py#L447) → `_settle_known` | B3 |
  | Publication race lost | [worker.py:450-456](../../server/src/anonymous/application/worker.py#L450) `_discard_publication` → `late_delivery` | B3 |
  | Verification after closure | `_verify_and_settle` → `_settle` (probe result) | B3, B4 or B5 from the router |

  The router discards undeclared bases only for probe results ([control.py:121](../../server/src/anonymous/application/control.py#L121)). Nothing else did, so a late `Completed` from an external binding would have freed the slot as B3.
- **F3.** An adapter-produced B4 through `probe` is admissible for an external binding ([test_handoff_protocol.py:339-343](../../server/tests/application/test_handoff_protocol.py#L339)); the only barrier was that the adapter did not declare it. The SQL trigger checks the handoff state, not `declared_bases` ([SQL:274-275](../../server/src/anonymous/adapters/persistence/sqlite/versions/0002_ld04_execution_ownership.sql#L274)).
- **F4.** The worker's `model_label` check ([worker.py:383](../../server/src/anonymous/application/worker.py#L383)) compares two values that, for an HTTP adapter that must not read `/props` or `/v1/models` (they expose the absolute model path, E2-B record §4), both come from configuration. It cannot detect a wrong model.

With no runtime evidence producer, stop and probe cannot release anything: an external binding's non-clean outcome quarantines the single slot across restarts ([test_reconcile.py:89](../../server/tests/application/test_reconcile.py#L89), [test_ownership_and_crash.py:285](../../server/tests/integration/test_ownership_and_crash.py#L285)).

## Decision

1. **Normal T4 success needs a complete, attributable, nonempty, accepted response.** Only such a response may publish through T4 and release the attempt slot. "Accepted" means Anonymous's own checks passed: instance and model labels equal the binding, the response is complete (`finish_reason: stop`), and the content is nonempty ([worker.py:378-392](../../server/src/anonymous/application/worker.py#L378)). T4 completion means **accepted response delivery**. It does **not** mean that the external process terminated, stopped generating, or is idle.
2. **Rejected responses manufacture no settlement evidence.** A truncated, empty, model-mismatched, unsaved or late response does not settle through B3/B4/B5. The run is closed and, because nothing admissible can end it, becomes `indeterminate` and quarantines the slot. This deliberately includes a plain `finish_reason: length`.
3. **HTTP 4xx/5xx alone does not establish terminal generation.** The adapter never returns `Knowledge.ENDED`. Every failure it reports (HTTP error, malformed, oversized, truncated or ambiguously framed body, dropped connection, timeout, an endpoint or identity that changed during the request, **and any request write that may have partly happened**) is `POSSIBLY_ACTIVE`. Only "nothing was written" is classified as such: a refused connection before any byte, or a listener that does not verify immediately before dispatch, is `NOT_STARTED` (B2), and an unverifiable runtime at `prepare` is `PrepareFailed` (B1). A write that fails part-way returns `UNKNOWN` at `start` and stays ambiguous: `await_result` then reports `POSSIBLY_ACTIVE`, never `NEVER_REACHED`.
4. **Binding declaration.** `lifetime_scope = EXTERNAL`, `declared_bases = {}` (empty, claiming no B3/B4/B5), `late_delivery_excluded = False`, `adapter_id = llama-dev-http`, `binding_format = llama-dev-http/1`. `instance_ref` is a per-launch nonce, never reused, with no path, URL or secret ([binding.py:3-5](../../server/src/anonymous/domain/binding.py#L3)). `start` returns `UNKNOWN` once the request is fully written (HTTP has no acknowledgment before the response, so `ACCEPTED` is never claimed) and `NOT_STARTED` before any write.
5. **Existing behavior is preserved.** `InProcessRuntime`, `ScriptedRuntime` and every owning-process binding behave as before; the guard in point 6 applies to `EXTERNAL` bindings only. No SQL, schema, trigger, domain type, evidence table, worker or LD-04 classification changes.
6. **One rule, enforced twice.** A pure rule in the domain (`basis_permitted_for_binding`): an `EXTERNAL` binding may rely on B3, B4 or B5 only if its adapter declared that basis. (a) `RunSettler.apply_evidence` returns without settling when the rule fails (logged without content). All six paths in the table above end there, so late delivery, terminal failure, rejected completion, the discarded-publication race and probe results are covered by one change; `_verify_and_settle` additionally filters its admissible set with the rule, so an undeclared probe result is not accepted even through a router that does not filter. The worker's existing fallback — a `None` result from `apply_evidence` leads to `close_and_verify` ([worker.py:407-408](../../server/src/anonymous/application/worker.py#L407)) — turns every rejected case into a closure and quarantine; the worker is not changed. (b) The SQLite store applies the same rule inside the one transaction that `settle_in_flight` and `settle_indeterminate` share, returning `NO_ADMISSIBLE_BASIS`, so a direct caller cannot bypass the settler. This is a Python check in existing code: no schema change and no migration. B1 and B2 are facts of Anonymous's own durable handoff record and are not restricted; owning-process bindings are unchanged.
7. **Disabled by default.** With no setting, composition builds `InProcessRuntime(FakeModelAdapter)` exactly as before. The real adapter needs `--runtime llama-dev` (or `ANONYMOUS_RUNTIME=llama-dev`) **and** an absolute launch-record path. A launch record set without selecting the runtime, an unknown runtime name, out-of-range limits, **and a missing, unsafe or malformed launch record or key file** refuse startup before the dataset is created or migrated (`preflight_runtime`, called by the entry point and by composition). Whether the recorded process is live is checked per attempt, not at startup. There is no silent fallback to another runtime.
8. **Dedicated, canonical, synthetic development dataset only.** With the real adapter the dataset path must be named `*-dev.sqlite3`, contain no `..`, and be canonical with no symlink in the path or its parents. This guards against accident; it cannot know what the dataset holds. Only synthetic development data may be used. Persisting personal data in it is outside this decision.
9. **One HTTP request, completely and unambiguously framed.** The adapter sends only `POST /v1/chat/completions`, non-streaming, with a configured `max_tokens`, to the exact `127.0.0.1` address and port of the launch record. It never requests `/health`, `/slots`, `/props` or `/v1/models`. A body is accepted only if its framing is complete and unambiguous: a single valid `Content-Length` that is fully received, or a complete chunked coding; a short or truncated body (`HTTPResponse.read(n)` does not raise on a short Content-Length body, so completeness is checked explicitly), a close-delimited body, an invalid `Content-Length`, **more than one `Content-Length` header (identical or conflicting; `http.client` parses only the first, so repetition is detected from the raw header list)**, and `Content-Length` together with chunked coding are rejected, and the size bound is kept. Request and response bodies, the key and paths are held in memory only and never logged or persisted. Failure messages are the fixed sanitized texts of [failures.py](../../server/src/anonymous/application/failures.py). `max_input_chars` is conservative (default 1400 for the pinned 2048-token context) so over-capacity input is refused before dispatch (B1).
10. **Runtime identity is external; attribution rests on kernel facts, not on the bearer key; weights are not thereby verified.** The server attaches to an independently launched process and never spawns, signals or adopts it. Immediately before dispatch (not only in `prepare`, which a slot wait can precede), `start` requires the recorded (pid, start) to be live **and** the sole listener on the exact address to be that process; otherwise nothing is written, so a prompt or the key is never sent to a listener known to be mismatched. Before a response is accepted the same two facts are re-established; a replaced, vanished or shared listener, or a changed process, is `POSSIBLY_ACTIVE` and quarantines. The per-launch bearer key only keeps other local clients away from the runtime; possessing it proves nothing about the identity of the server that answered, and it is never used as attribution. **Residual race (accepted for the localhost development threat model):** a listener swapped between a check and its use is detected only if the swapped state persists until the post-response check; a process that answers and then restores the original listener before that check, or a hostile same-user process (which can read the key file and process table), is not defended against. Closing it would need connection-level peer attribution (for example the owner of the established socket), a larger change not made here. Digests are recorded with their basis: from the pins they are `asserted`; only a digest the launcher itself computed over the file it launched (`--hash`) is `verified`; otherwise the component is label-only. The binding's `model_label` equality is a configuration constant and is **not** a model-identity check. A replacement window between hashing and loading is an accepted residual (E2-B §16).
11. **Launcher and cleanup are identity-verified, fail closed and settle nothing.** A process is identified only by its recorded kernel (pid, start), verified live immediately before the tool sends SIGTERM to that one process; the tool never signals a group or "whatever holds the port", never escalates to SIGKILL, and refuses on any mismatch (exit code 3, nothing signalled). **An inconclusive inspection is not absence:** `identity_of` returns `None` only when the kernel positively reports no such process (`ESRCH`) and otherwise raises `IdentityUnavailable`; on any such failure the tool deletes no key or record, never replaces a previous record, and signals nothing. **Launch is protected end to end:** the record path is validated before anything is created (absolute, canonical, no `..`, no symlink); a durable *launch intent* file is written and synced before the spawn and removed only once the record is durable, so an interrupted launch leaves discoverable recovery state and further launches are refused until an operator resolves it; any failure after the spawn is contained through the `Popen` handle (the pid cannot be reused while the unreaped child is held, so that is identity-safe) and the key, intent and log are deleted only if the child is confirmed gone; if it cannot be shown to be gone, everything is retained and the pid and start identity are reported for manual, verified recovery. **Artifact ownership:** the intent is the first artifact created (exclusively); the launcher deletes only files it created, so a launcher that loses the intent race refuses and never touches the winner's intent. **An uncertain spawn is not guessed:** if the spawn was entered but no handle came back (an interrupt during `Popen`), the intent, key and log are retained and the nonce and port are reported (`spawn_status_unknown`), because a child may exist. **A retained intent identifies a possible survivor only through its nonce**, which appears in the runtime's own command line as `--api-key-file …/key-<nonce>`; the intent holds no pid. The operator procedure (locate by nonce, verify uniqueness and identity, signal one process or nothing, and when the retained files may be deleted) is in the [implementation record](../implementation/v0-1-external-runtime-dev.md); it never recommends termination by process name or by port and it changes nothing in SQLite. **Unavoidable residual:** an uncatchable termination (SIGKILL, power loss) of the launcher between the spawn and the record leaves a possible uncontained child; only the durable intent, key and log remain, which is sufficient for the manual nonce-based recovery. Expected filesystem failures are reported by code only, never by path. The tool imports no persistence or application code and cannot reach SQLite; stopping or cleaning a runtime changes no run (design §6.5). It uses the E2-B/E3 launch profile (no-fork sandbox, loopback, allow-listed environment, per-launch key file 0600 in a 0700 directory, own session). **Residual:** between the final identity check and `kill(2)` a pid could in principle be reused; the window is short but not bounded (scheduling or suspension can lengthen it), the same residual as the E3 pilot's.
12. **Classifications and frozen artifacts are untouched.** No LD-04 row is promoted; E1, E2-B and E3 evidence and tools are not changed.

A non-clean outcome may quarantine the disposable dev dataset for good; the supported recovery is a new dataset file, with the old file's history still readable. There is no automatic or silent reset, no force release and no operator attestation (CB-05, O1; a force release needs its own ADR).

## Conflict check against existing contracts

Result: **no conflict, no schema migration, no change to accepted lifecycle semantics for any existing adapter.**

- An empty `declared_bases` is storable and read back: the T3 trigger tests `IS NULL`, not emptiness ([SQL:234](../../server/src/anonymous/adapters/persistence/sqlite/versions/0002_ld04_execution_ownership.sql#L234)); the store writes `""` and parses it back to an empty set ([store.py:750, 107](../../server/src/anonymous/adapters/persistence/sqlite/store.py#L107)). Covered by `test_an_empty_declaration_round_trips_through_dispatch`.
- T4 still stamps `runtime_reported_terminal` (F1). Its meaning is clarified, not changed: for an `EXTERNAL` binding without declared B3 it is "accepted response delivery". No new basis value or column (a migration) is introduced; the meaning is recoverable from the binding row.
- The changes to accepted code are confined to `settling.py`, the store's shared settlement transaction and one pure domain helper, all acting on `EXTERNAL` bindings only. Every pre-existing adapter and test declares the bases it uses, so the 302 pre-existing tests pass unchanged.
- The router's guard-based B4 for `OWNING_PROCESS` bindings of an earlier boot is untouched.
- **Store-level enforcement needs no migration.** The earlier draft deferred a store check as a migration; the independent review showed it is a Python check in the shared `_settle_failed` transaction (`settle_in_flight` and `settle_indeterminate`), covering direct callers. The SQL trigger is unchanged and still checks only the handoff state; the store's Python check is now the second enforcement point.

## Alternatives considered

- **Declare B3 and accept late or rejected deliveries as B3 (the previous behavior).** Rejected: ADR-0013 reserves B3–B5 for scripted adapters until measured; E3's Reader was passive and qualifies nothing.
- **Classify complete HTTP error responses as `ENDED` (revision 1 of this ADR).** Rejected by the owner: a status code alone does not show that generation ended.
- **Settle rejected-but-complete responses (truncated, empty) to avoid quarantine (revision 1).** Rejected by the owner: it would manufacture B3 for responses Anonymous does not accept.
- **Guard only `late_delivery`.** Rejected: terminal-failure, rejected-completion and probe paths reach the same function and would remain open.
- **Wrap the HTTP client as a `SynchronousModel` in `InProcessRuntime`.** Rejected: it would record `owning_process` and `late_delivery_excluded = True`, making a later boot's guard false B4 evidence for a process that outlives its owner (E3 O5).
- **Have the Anonymous server spawn and own the runtime.** Rejected for v0.1: Owner death does not stop the runtime, so ownership would still need a verified exit producer the owner has not accepted.
- **Let the launcher or cleanup tool produce B4 to release a quarantine.** Rejected by owner decision.
- **An operator `reset` or force release.** Rejected: weakens CB-05; needs its own ADR.
- **A new termination-basis value or column for "accepted response delivery".** Deferred: needs a migration and an evidence-table change.
- **A trigger-level (SQL) `declared_bases` check.** Deferred: a migration; the store's Python check and the settler's check are sufficient for this scope.

## Consequences

- The first real conversation is possible with no schema, trigger, worker or client change. `settling.py`, the store's shared settlement transaction and one domain helper change accepted 0B-1 code, for `EXTERNAL` bindings only.
- **Any rejected, ambiguous or failed response quarantines the whole dev dataset**, including a response cut off by `max_tokens`, an empty reply, an HTTP error and a deadline. A bounded `max_tokens`, a conservative `max_input_chars` and a deadline well above the observed generation time keep this rare; it remains a real availability cost, accepted for development only. Context overflow is the one avoidable cause the adapter cannot fully prevent (the character bound is a proxy for tokens).
- A surviving runtime keeps generating and discards the output (E3 O5); the cleanup tool is the supported way to stop it and settles nothing.
- `termination_basis = runtime_reported_terminal` on a succeeded external run must be read per point 1. Later evidence reports, UI or audit work must not treat it as B3 qualification.
- The model-label check does not protect against a wrong model being loaded; only a `verified` digest could, and only for what the launcher hashed.
- Privacy depends on adapter discipline (single endpoint, no body persistence, fixed messages), enforced by tests, not by the runtime. The runtime's own log, the launch record and the launch intent contain local paths and must stay local; they are never committed.
- **Attribution is bounded by the localhost development threat model** (point 10): kernel facts checked before dispatch and before accepting a response, with the residual race stated there. Stronger peer attribution is a larger change and needs an owner decision before any non-development use.
- Unchanged and not accepted here: control during generation, per-attempt registration, B3/B5 qualification, `late_delivery_excluded`, cancel, disconnect, reproducibility, GPU offload, Windows, authentication and access containment, submission fencing, streaming, personas, memory.

## Implementation status (development only, for review)

Implemented 2026-10-24 and remediated after the independent Codex review (BLOCKED, seven findings F1–F7, all accepted and corrected the same day); not run against a real model or runtime:

- New: `server/src/anonymous/adapters/model/` `llama_http.py` (RuntimePort adapter), `llama_launch_record.py` (record and key reader/writer), `llama_ctl.py` (launcher and cleanup CLI, script `anonymous-llama-dev`), `process_identity.py` (macOS libproc and `lsof` facts).
- Changed: `domain/evidence.py` (the pure rule), `application/settling.py`, `adapters/persistence/sqlite/store.py` (shared settlement transaction), `config.py`, `composition.py` (`preflight_runtime`), `__main__.py`, `pyproject.toml` (script entry only; no dependency).
- Tests (all synthetic; a fake loopback HTTP server and stand-in processes; no runtime, model or network beyond an ephemeral 127.0.0.1 listener): `tests/adapters/`, `tests/application/test_external_settlement_guards.py`, `tests/unit/test_runtime_config.py`. Results on the final files: 486 server tests pass (the 302 pre-existing unchanged plus 184 new), `ruff` and strict `mypy` clean; see the [implementation record](../implementation/v0-1-external-runtime-dev.md), which also lists what is NOT TESTED (the real launcher, sandbox and Qwen behavior).

Open for owner acceptance of this ADR: the quarantine-on-rejection consequence; the `UNKNOWN` start acknowledgment; the conservative `max_input_chars` default; the launch profile's fixed `-t 6`; macOS-only identity facts; the attribution residual of point 10 (and whether connection-level peer attribution is wanted before any use beyond development); the unbounded pid-reuse window of point 11. A real-model smoke needs a separate authorization and a sanitized record, and is limited by the operating conditions of the first attended smoke recorded in the implementation record (synthetic data only, loopback only, attended launcher lifecycle, no concurrent competing launch, no production PRIVATE-mode claim, a fresh disposable database, identity-safe cleanup and post-run inspection, and no restart or reset to escape a quarantine).
