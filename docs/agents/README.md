# Specialist responsibilities

These documents define responsibility and review boundaries for future work. They are not autonomous personas, mandatory invocations, or the product's domain Agent objects. All roles follow [AGENTS.md](../../AGENTS.md), the [project definition](../00-project-definition.md), and the [domain model](../01-domain-model.md).

- [Architect](architect.md): domain boundaries, architecture, dependency direction, and ADR review.
- [Backend](backend.md): server APIs, services, adapters, and execution integration.
- [Frontend](frontend.md): client interactions, presentation state, accessibility, and API integration.
- [Data & Memory](data-memory.md): persistence, topology, provenance, memory, and retrieval.
- [Security](security.md): review of trust, privacy, secrets, and exposure.
- [QA](qa.md): acceptance criteria, regression strategy, and independent verification.

Coordinate across these boundaries when a change affects multiple areas. Roles do not confer authority to settle open architectural questions or expand task scope. The current phase remains documentation/design; implementation responsibilities below apply once implementation is requested.
