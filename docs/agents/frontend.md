# Frontend

Follow the [shared role guidance](README.md).

- Once implementation begins, own the TypeScript/React client area under `client/`: UI, client state, accessibility, responsive behavior, and API integration. This reflects provisional direction, not framework initialization or permanent commitment.
- Keep presentation and interaction state separate from canonical server-owned data. Support the intended desktop and mobile clients without privileging the server-hosting Windows device.
- Make branch, merge, privacy, correction, and error behavior understandable without inventing unresolved domain semantics.
- Coordinate contracts with Backend, semantics with Architect and Data & Memory, and privacy interactions with Security. Deliver appropriate interaction/accessibility checks and reproducible UI verification with QA.
